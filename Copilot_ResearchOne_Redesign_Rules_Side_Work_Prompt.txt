REQUIRED BRANCH-WORKFLOW DESIGN

Rewrite Rule 32 and its mirrors around an ordered integration strategy:

1. PREFERRED: EXISTING ASSIGNED PR BRANCH
   - If the coding environment supplies a non-default branch, use it.
   - Verify it is based on current origin/main.
   - Do not attempt to create another branch unnecessarily.

2. NORMAL: CREATE A DEDICATED PR BRANCH
   - If ref creation is permitted, create the branch from fresh origin/main.
   - Push and open/update a PR normally.

3. RESTRICTED-CREATION ENVIRONMENT
   - If GitHub returns GH013 “Cannot create ref due to creations being restricted,” stop retrying branch creation.
   - Check whether the task provides an existing writable branch.
   - If one exists, use it and open/update its PR.
   - If none exists, report:
     * exact branch name attempted;
     * base SHA;
     * exact GH013 message;
     * that a repository ruleset/admin change or pre-created branch is required.
   - Do not pretend that a local-only branch is deliverable.

4. EXPLICIT DIRECT-MAIN EXCEPTION
   - Only when the user explicitly authorizes direct main in the same task.
   - Require [direct-main] in the commit message.
   - Keep the current CI gate.
   - Direct-main is an exception, not the new default.

5. NO-DEADLOCK REQUIREMENT
   - An agent must not be trapped between:
     * “you must create a PR branch before any edit”; and
     * a GitHub ruleset that forbids creating the branch.
   - In that state, the required behavior is deterministic escalation, not endless retries or silent local work.

UPDATE scripts/git/prepare-work-branch.sh

Make this helper safe and informative:

- Run git fetch origin.
- If already on a non-default branch supplied by the environment, support an explicit reuse mode rather than resetting it.
- Never reset or overwrite an existing branch with uncommitted work.
- Detect working-tree changes and refuse destructive checkout/reset behavior.
- When branch creation/push fails with GH013, print a concise structured message:

  BLOCKED_GITHUB_REF_CREATION
  attempted_branch=<name>
  base=origin/main
  resolution=use an existing writable branch, pre-create the branch, or change the GitHub ruleset/bypass

- Do not claim the local checkout itself proves the remote branch can be created.
- Note that local git checkout can succeed while the later remote push fails. The helper or associated instructions must distinguish local branch creation from remote ref creation.

Do not add credentials, bypass GitHub restrictions, or use force push.

UPDATE scripts/git/assert-not-on-main-branch.sh

- Preserve refusal on main by default.
- Preserve ALLOW_DIRECT_MAIN_PUSH=1 as an explicit same-task override.
- Improve its error message so restricted-ref environments receive both supported choices:
  1. use/pre-create a writable PR branch;
  2. obtain explicit direct-main authorization.
- Do not automatically enable direct-main.
