# Work Order X — Academic Formatting Engine (Pandoc + xelatex + CSL + Lossless Evidence Aliases)

**Goal.** Ship the surface where ResearchOne's audit-grade positioning lands as a file a peer reviewer, patent examiner, or court clerk will accept without remediation: a `POST /api/reports/:id/export?format=docx|pdf|md|html&style=mla|apa|chicago-author-date|chicago-note|ieee|harvard` endpoint that takes a published report, assigns Lossless Evidence Aliases (`[E1]`, `[E2]`, ... per report, stored in `evidence_aliases` with snapshotted CSL-JSON so the citation form is frozen at assignment time and survives later source edits), runs Pandoc as a sandboxed subprocess with `xelatex --no-shell-escape`, and produces a styled output file. Adds a new `citation_formatter` role to `REASONING_MODEL_ROLES` for the bounded judgement calls Pandoc itself can't make (incomplete date inference, ambiguous author institutional vs. personal classification). This is THE load-bearing cross-WO contract: per Cursor rule 25 invariant I-9, the same commit that adds the role MUST add its `case 'citation_formatter': return 'Citation Mapping';` to WO-U's `costSidecar.ts:rolePhaseFor()`. Frontend: a `ReportExportButton` opens a format/style modal, streams sync exports inline, polls async exports through to completion. Deploy-skew tolerance extended to system binaries: if Pandoc is not installed, the endpoint returns `{available: false, reason: 'pandoc_not_installed'}` with HTTP 200 and the button renders disabled with a tooltip. The format-engine subprocess layer is the highest-risk security surface in the codebase (untrusted markdown executes through Pandoc which delegates to a Turing-complete TeX macro system) — Rule 28 makes the boundaries explicit: untrusted content flows via stdin/tempfile never argv, every invocation has a wall-clock timeout, every invocation runs in a per-job tempdir cleaned in `finally`, xelatex runs with `-no-shell-escape`, and format/style parameters are enum-validated at the API edge.

**Files to create.**

Cursor rule `.cursor/rules/28-academic-formatting-engine.mdc`: ten invariants. The load-bearing ones repeat above. Pre-commit checks include the Rule 25 I-9 mechanical cross-WO grep: `git diff --name-only | grep -E "reasoningModelPolicy\\.ts|costSidecar\\.ts"` — both files must appear in any diff that touches either.

Migration `backend/src/db/migrations/032_formatting_engine.sql`: two tables. `evidence_aliases` carries `(report_id, citation_id, alias TEXT, ordinal INTEGER, csl_json JSONB)` with unique constraints on `(report_id, citation_id)` and `(report_id, ordinal)` so aliases are stable per Rule 28 I-8 and ordinals are unique per report. `report_exports` carries async job records: `(report_id, user_id, format, style, status, output_url, output_bytes, error_class, error_detail, pandoc_duration_ms, queued_at, started_at, completed_at)`. All FK constraints in `DO` blocks per Cursor rule 13. Idempotent.

Formatting services `backend/src/services/formatting/`:

- `cslConverter.ts` — pure function `sourceToCslJson(row, opts?)`. Maps the 14 `source_type` enum values to CSL types, parses author strings (Last,First / First Last / institutional via heuristic), parses dates with year/year-month/year-month-day precision graceful degradation, handles missing `published_at` by emitting `accessed` from `metadata.ingested_at`, preserves source row id in `note: source_id:...` for traceability. Per Rule 28 I-7: zero side effects, every test is a snapshot.

- `evidenceAliaser.ts` — `assignEvidenceAliases(reportId, opts?)` loads existing aliases first, scans citations in canonical order (section position then created_at), assigns new ordinals to never-seen citations and persists them with snapshotted CSL-JSON. `ON CONFLICT (report_id, citation_id) DO NOTHING` handles concurrent export jobs racing. `rewriteAliasesForPandoc(body)` replaces `[E1]` with `[@E1]` (pandoc citation syntax) using a negative-lookbehind regex so it's idempotent on already-rewritten bodies. `aliasesToCslBibliography` converts to the array-shape pandoc consumes via `--bibliography`.

- `pandocRunner.ts` — `runPandoc({markdown, cslJson, format, style, timeoutMs?})`. Captures untrusted markdown and CSL-JSON into a per-job tempdir under `/tmp/r1-export-<uuid>/`, spawns pandoc with hardcoded safe argv (stdin reserved for `--version` probe; export jobs use tempfile path arg, not content), enforces wall-clock timeout via `setTimeout` + `SIGKILL`, sets `--pdf-engine-opt=-no-shell-escape` and `-halt-on-error` for the xelatex path, runs the subprocess with a curated env (PATH only, no parent env to avoid leaking secrets), returns `{outputPath, outputBytes, durationMs, stderr}`. `pandocAvailable()` is a once-and-cached `pandoc --version` probe; the cache is process-lifetime. `PandocError` classifies failures as `pandoc_not_installed | timeout | pandoc_error | xelatex_error | validation_error` for the API layer's response mapping. `validateArgs()` is defense-in-depth — re-checks the format/style enums even though the API layer already did.

- `exportOrchestrator.ts` — `exportReport({reportId, format, style, userId?})`. Wraps the entire body in `runScope.run({reportId, userId, runId: null})` so any LLM calls (currently only `citation_formatter`) get tagged with the right scope per WO-U. Loads the report body, calls `assignEvidenceAliases` to ensure aliases exist for every citation, calls `rewriteAliasesForPandoc` to convert `[E1]` to `[@E1]`, wraps the body in a minimal YAML title-block, builds the CSL bibliography, invokes `runPandoc`, reads the output buffer before the tempdir is cleaned, returns `{outputBuffer, outputBytes, pandocDurationMs, aliasCount}`.

- `exportStorage.ts` — `uploadExportOutput({exportId, format, buffer})`. Three backends behind one interface keyed on `EXPORT_STORAGE_BACKEND` env: `local` (writes to `/var/r1-exports/<id>.<format>`, returns a relative URL served by an authenticated static-file route), `s3`/`r2` (stubs for object-storage paths — implement when production needs them; the interface contract is in place). Returns a URL the polling endpoint stores in `report_exports.output_url`.

CSL stylesheet templates committed under `backend/src/services/formatting/templates/citation-styles/`: `mla.csl`, `apa.csl`, `chicago-author-date.csl`, `chicago-note.csl`, `ieee.csl`, `harvard.csl`. **Cursor: download these from `https://github.com/citation-style-language/styles` (the official CSL repo, CC BY-SA license, in-tree-friendly) and commit them. Do not link out at runtime.** Reference `.docx` templates under `templates/`: `mla-reference.docx`, `apa-reference.docx`, `chicago-reference.docx`. **These are generated once via `pandoc --print-default-data-file=reference.docx > templates/<style>-reference.docx` then hand-edited to set the correct font, margins, spacing per the style guide. Binary committed.** Document the generation process in `templates/README.md`.

BullMQ worker `backend/src/queue/workers/reportExportWorker.ts`: drains the `report_export` queue. UPDATE status='running' → call `exportReport` → `uploadExportOutput` → UPDATE status='completed' with output_url. On PandocError, UPDATE status='failed'/'timed_out' with error_class and truncated error_detail. Job concurrency: 2 per worker (xelatex is RAM-heavy). Lock duration 90s (belt-and-suspenders over pandoc's own 30/60s timeout).

Tests `backend/src/__tests__/formattingEngine.test.ts`: three test groups in one file. `cslConverter` — snapshot mapping for every source_type, multi-format author parsing, date precision degradation, missing-date accessed fallback. `evidenceAliaser` — alias rewrite, idempotency, non-alias bracket leave-alone. `pandocRunner` — input validation (format/style enums, non-string markdown), shell-injection regression that confirms a markdown body containing `$(rm -rf /)`, backticks, and `;` produces either a successful render (CI with pandoc) or a `pandoc_not_installed` error (CI without) but NEVER side-effects on the filesystem. The integration suite (separate file in CI's Docker-with-pandoc lane) asserts the full subprocess round trip.

Frontend `frontend/src/components/reports/ReportExportButton.tsx`: button + modal. Format select (DOCX/PDF/MD/HTML), style select (six citation styles). Sync path streams the file blob inline for MD/HTML; async path POSTs, polls `/reports/exports/<exportId>` every 2s up to 60 attempts. When the server returns `{available: false, reason: 'pandoc_not_installed'}` (Rule 28 I-6), renders an amber banner with operator-facing copy and disables the Export button. Loading states for both rendering and polling phases via lucide-react `<Loader2>`.

- A user views a report and clicks Export → modal opens. Selects format=APA, style=APA, format=DOCX. Clicks Export. The async path enqueues a job; modal shows the polling loader. ~5–10 seconds later, the rendered .docx downloads automatically.
- Opening the downloaded .docx in Word shows: the report title as a heading, the body text with in-text citations formatted per APA 7th ed. ("Lane, 2026"), and a "References" section at the bottom with full-form citations alphabetized per APA. No hallucinated authors. Every citation traces back to a real `sources` row.
- Re-exporting the same report a week later produces the same `[E1]`, `[E2]`, `...` alias mapping → same in-text citation order → semantically equivalent document. Lossless Evidence Aliases (Rule 28 I-8) holds.
- A user clicks Export → MLA + PDF. The async job runs through xelatex. ~30–60 seconds later, the .pdf downloads. The .pdf renders with the correct font (per the MLA reference docx), 1-inch margins, double-spacing, Times New Roman 12pt, and MLA-style Works Cited at the bottom.
- A user clicks Export → Markdown + APA. The sync path streams the .md file inline. The downloaded .md contains the body with `[@E1]` pandoc citation syntax already resolved to `(Lane, 2026)` since pandoc was applied (markdown export goes through pandoc for citation rendering, not just as raw markdown pass-through).
- An admin views the WO-U cost dashboard. The Phase breakdown chart now includes a "Citation Mapping" slice. Filter the per-run cost table by `phase=Citation Mapping` — it shows export-time rows. **This is the working cross-WO contract — Rule 25 I-9 firing live.**
- A user attempts an export on a server without pandoc installed. The modal renders the amber "Export not available — Pandoc is not installed on this server" banner. The Export button is disabled. No 500 in the API logs.
- A malicious user submits a report (or seeds a source with metadata) containing `$(rm -rf /)`, backticks, `;`, `&&`. The export job completes and produces a .docx with those characters as LITERAL TEXT in the body. The server's `/tmp` directory contains the cleaned scratch directory but no `pwn` file or similar evidence of shell evaluation.
- A user submits an export with `format=xlsx` or `style=turabian-9`. The API returns HTTP 400 with `{error: 'invalid format', validFormats: [...]}` or `{error: 'invalid style', validStyles: [...]}`. Pandoc is never invoked.
- An export job takes longer than 30 seconds (DOCX) or 60 seconds (PDF). The subprocess is SIGKILL'd. The job record updates to `status='timed_out'`, `error_class='timeout'`, `error_detail='pandoc timed out after 30000ms'`. The user sees a clear error in the modal.
- The export worker crashes mid-job. Re-enqueuing the same job via BullMQ's retry policy produces the same output (idempotency via the stable alias mapping). The user's polling sees `status=failed` → BullMQ retries → `status=running` → `status=completed` without manual intervention.

**Critical reminders.**

1. **PATCH-X01 and PATCH-X02 land in the SAME commit.** This is the load-bearing cross-WO contract you've been wiring across WO-U (Rule 25 I-9 invariant) and WO-X (Rule 28 I-1 enforcement). The pre-commit grep `git diff --name-only | grep -E "reasoningModelPolicy\\.ts|costSidecar\\.ts"` must show both files. If a Cursor PR shows only one, REJECT — splitting them produces silent cost mis-attribution. The mechanical test `rolePhaseFor('citation_formatter') === 'Citation Mapping'` is the tripwire.
2. **Untrusted content NEVER touches argv.** Per Rule 28 I-2. The `pandocRunner.ts` interface accepts `markdown` and `cslJson` as values, writes them to per-job tempfiles, and passes the tempfile PATH (a server-controlled string) to pandoc as argv. If a future PR adds a parameter like `extraPandocArgs?: string[]` or a "trust me bro" override, REJECT — the security boundary IS the API surface. The pre-commit grep `grep -rn "exec\\|spawn" backend/src/services/formatting/ | grep -v __tests__ | grep -v pandocRunner.ts` must return empty.
3. **xelatex runs with `-no-shell-escape`.** Per Rule 28 I-3. xelatex's `\write18` mechanism is arbitrary shell command execution from inside a TeX document. The flag disables it. If a future PR removes the flag claiming "we need shell-escape for some package" — REJECT — find another way. Pandoc + xelatex without shell-escape is a complete, well-supported configuration; nothing in the academic citation use case requires `\write18`.
4. **Every Pandoc invocation has a wall-clock timeout.** Per Rule 28 I-4. Default 30s for DOCX/MD/HTML, 60s for PDF (xelatex is slower). The timeout is enforced in `runPandocSubprocess` via `setTimeout` + `SIGKILL`. A future PR that removes the timeout because "the user said they wanted a big report" — REJECT — the worker pool is small and a wedged pandoc takes down the whole queue. Per the V2 outage postmortem precedent.
5. **Per-job tempdir, cleaned in `finally`.** Per Rule 28 I-5. `mkdtemp(/tmp/r1-export-)` per job, `rm -rf` in `finally`. Even when the function throws. Even when the timeout fires. Pandoc has filesystem reach via `\input{...}` and similar; the tempdir is the containment.
6. **Pandoc availability is a runtime check, not a build flag.** Per Rule 28 I-6. The deploy-skew tolerance extended to system binaries. `pandocAvailable()` runs `pandoc --version` once at startup, caches. Missing pandoc → API returns `{available: false}` → frontend disables button with tooltip. No 500. This is critical during the system-binary rollout window: when prod is being updated to install pandoc, some replicas have it and some don't, and the app must not crash on the ones without.
7. **CSL conversion is a pure function with snapshot tests.** Per Rule 28 I-7. Snapshot fixtures are the contract. When a Cursor PR changes a field mapping, either the snapshot updates in the same diff (the change is reviewable) or the test fails. Don't bypass snapshots with mocks.
8. **Lossless Evidence Aliases are stable per (report, citation).** Per Rule 28 I-8. The unique constraint on `evidence_aliases(report_id, citation_id)` is the enforcement; the alias and the snapshotted CSL-JSON together preserve the citation form through later source-row edits. If a revision creates a new report version (per WO-T), aliases regenerate for the new report — they are NOT shared across versions. A reader citing the May 2026 export of Report-X by `[E5]` can re-export May 2026's Report-X any time and get the same `[E5]` mapping; the August 2026 revision Report-X' has its own alias series, which is correct.
9. **Format and style are enum-validated at the API edge.** Per Rule 28 I-9. The API route's `VALID_FORMATS` and `VALID_STYLES` sets are the security boundary. `pandocRunner.ts` re-validates as defense-in-depth. If you add a new format or style, you add it in BOTH the route enum and the frontend dropdown enum in the same commit, plus a CSL/template file for any new style.
10. **CSL files and reference DOCX templates ship vendored in-repo.** Per Rule 28 pre-commit check. Do NOT fetch from `https://github.com/citation-style-language/styles` at runtime — the CSL repo is CC BY-SA, in-tree-friendly. Committing the styles makes the build reproducible and removes a runtime network dependency on a third-party GitHub repo.
