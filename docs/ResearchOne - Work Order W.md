# Work Order W — Animated Multi-Agent Pipeline Hero

**Goal.** Replace the static 4-phase pipeline visual on the landing hero with an animated 10-stage flow — directed beams of light pulse along an S-curve through the canonical agent nodes (Planner → Discovery → Retriever → Retriever Analysis → Reasoner ⟶ Skeptic → Synthesizer → Verifier → Report → Epistemic Persistence), with the Skeptic node visibly distinguished per the Master Brief positioning. The animated visual reads `data-persona` from WO-V's `PersonaAwareHero` and switches beam color palette per buyer tribe (default cyan, OSINT cool blue, UAP violet/magenta, academic teal/gold, patent amber/green). Reduced motion users get the exact existing static `HeroPipelineVisual` rendered byte-identically — no degraded animation, no opacity transitions — so WCAG 2.1 SC 2.3.3 is upheld and the existing accessibility-validated baseline serves as the fallback. Mobile viewports (<768px) also render the static visual because the 10-stage S-curve does not survive narrow viewports gracefully. The animation pauses when the hero scrolls out of view (IntersectionObserver gate). No SVG filter chains on the critical path — the glow effect is achieved by stacking a wider, lower-opacity stroke beneath the bright beam, validated to hold 60fps on a 2021 mid-range Android. Composes onto WO-V (mounts inside `LabNotebookCanvas`, reads persona from the wrapping section) and is fully independent of WO-U (cost telemetry).

**Pre-work.** Read `.cursor/rules/00-pre-commit-review.mdc` (master checklist), `.cursor/rules/26-landing-persona-and-visual.mdc` (the composition contract — WO-V exposes `data-persona`, WO-W reads it), and `.cursor/rules/27-animated-pipeline-hero.mdc` — the ten invariants for this WO. The load-bearing ones: I-1 reduced motion renders the existing static visual verbatim, I-2 the static visual is imported and never edited, I-3 the 10 stages are public marketing surface and not renamed without coordination, I-4 Skeptic remains the visually distinguished node, I-5 beam palette is read from `data-persona`, I-6 animation pauses when off-screen, I-7 no `filter: drop-shadow` or `filter: blur` on the critical path (40% framerate hit on the test device), I-8 ARIA preserved with decorative SVG marked `aria-hidden`, I-9 palettes pass color-blindness simulation, I-10 tests-must-fail-without-the-fix. Existing files to read end-to-end: `frontend/src/components/landing/HeroPipelineVisual.tsx` (93 lines — the static baseline this WO does NOT edit), `frontend/src/components/landing/persona/PersonaAwareHero.tsx` (the parent that exposes `data-persona`), `frontend/src/components/landing/persona/personaResolver.ts` (the `PersonaId` type WO-W reuses), and `frontend/package.json` line containing `framer-motion ^11.15.0` (already installed — no new dep needed).

**Files to create.**

Cursor rule `.cursor/rules/27-animated-pipeline-hero.mdc`: ten invariants. The load-bearing ones repeat above. Pre-commit checks grep for: `useReducedMotion` usage in the animated module, absence of `filter: drop-shadow|blur` and `<filter` anywhere in the four new files, presence of `HeroPipelineVisual` as imported (not duplicated), and same-commit consistency between any new persona id and a corresponding beam palette entry.

Visual modules `frontend/src/components/landing/visual/`:

- `pipelineLayout.ts` — canonical geometry for the 10 stages. `PipelineStage` interface with `id` (lowercase snake_case, used in tests as React key — stable contract), `label` (display string), `phase` (`'plan' | 'retrieve' | 'reason' | 'synthesize'` — matches WO-U cost analytics phases for cross-WO color-coding when relevant), optional `emphasis` flag (only true for Skeptic), `x` and `y` in a 1000 × 360 viewBox. Layout is a snake: top row left-to-right (Planner → Reasoner), curve turn down to Skeptic, bottom row right-to-left (Skeptic → Persistence). `PipelineEdge` interface with `id`, `fromId`, `toId`, pre-computed SVG path `d`, and `seq` index for stagger sequencing. Most edges are straight horizontal paths; the Reasoner → Skeptic turn is a smooth quadratic bezier. Timing constants: `PIPELINE_CYCLE_MS=4500`, `PIPELINE_STAGGER_MS=350`, `PIPELINE_LOOP_PAUSE_MS=800`.

- `personaBeamPalettes.ts` — `BeamPalette` interface with `beamHead` (brightest, the moving "pulse" point), `beamMid` (visible tail), `beamTail` (fades to transparent rgba), `trackColor` (static line color visible between passes), `nodeIdleRing`, `nodeActiveRing`, `skepticRing` (brightest in the palette — the marketing differentiator). Five palettes: default (cyan, matches `r1-accent`), osint (cool blue / near-white skeptic), uap (violet/magenta — drifts from "responsible business SaaS" because the UAP community evaluates seriousness via aesthetic refusal to match institutional templates per the strategic doc), academic (teal with amber skeptic — peer-review highlight), patent (amber with green skeptic — novelty-confirmed marker). All palettes pass deuteranopia/protanopia/tritanopia simulation because the primary contrast vector is BRIGHTNESS not hue. `getBeamPalette(persona)` does a safe lookup with default fallback for unknown ids.

- `pipelineBeams.tsx` — the SVG beam layer. Two stacked stroked paths per edge: a static low-opacity track always visible, and an animated bright stroke. Per Rule 27 I-7, the "glow" is faked with a wider stroked halo path underneath the bright beam using `mix-blend-mode: screen`, NOT with `filter: drop-shadow()`. Each beam animates via Framer Motion's `pathLength` and `opacity` keyframes with per-edge `delay` offsets to create the staggered sequential flow. `repeat: Infinity` with computed `repeatDelay` produces the loop. The SVG element is `aria-hidden="true"` and decorative. When `active=false` (off-screen), beams animate to `{pathLength: 0, opacity: 0}` — pause without removal so re-entry resumes smoothly.

- `AnimatedPipelineHero.tsx` — the main component. Five behavioral modes resolved in order: (1) reduced motion → render `<HeroPipelineVisual />` byte-identically and return (Rule 27 I-1); (2) mobile (<768px) → also render `<HeroPipelineVisual />` because the S-curve does not work on narrow viewports; (3) desktop animated → render the SVG beams, absolute-positioned HTML nodes with persona-tuned rings, phase labels along the top edge. Persona resolution happens in a `useEffect` that reads `containerRef.current.closest('[data-persona]')` to find the ancestor section (set by WO-V's `PersonaAwareHero`). IntersectionObserver gates the animation on viewport visibility (threshold 0.25 — Rule 27 I-6). Three test-only props: `forcePersona`, `forceReducedMotion`, `alwaysAnimate` (bypass IntersectionObserver in vitest).

Test `frontend/src/__tests__/landing/AnimatedPipelineHero.test.tsx`: 13 assertions across seven describe blocks. Every assertion ends with `// REVERT-CHECK:` per Rule 27 I-10. Coverage: reduced-motion fallback renders static and not animated; the static fallback retains the aria-label; animated render produces the SVG and the screen-reader description; all 10 canonical stage labels appear in the DOM (the tripwire for Rule 27 I-3 — if marketing renames a stage in the layout file without coordination, this fails); Skeptic node carries `data-emphasis="skeptic"` and uses the brighter `skepticRing` color; persona palette swap works for forced osint/uap/patent and falls back safely for unknown ids; SVG carries `aria-hidden="true"`; rendered DOM contains no `filter: drop-shadow|blur|<filter` (the Rule 27 I-7 tripwire); persona detection via ancestor `[data-persona]` works (the WO-V → WO-W composition contract).

- A visitor at `/?p=uap` sees the same animation with violet/magenta beam palette and a saturated-rose Skeptic ring. The persona attribute on the wrapping section flows automatically to the beam component via DOM lookup.

- A visitor at `/?p=academic` sees teal beams, amber Skeptic ring.
- A visitor at `/?p=patent` sees amber beams, green Skeptic ring.

- Scrolling the pipeline panel out of viewport: DevTools Performance shows the JS RAF cost drop to near-zero. Scrolling back in: beams resume.
- DevTools Rendering → "Emulate vision deficiencies" → Deuteranopia: beam pulses remain clearly visible against the track. Same for protanopia and tritanopia. (Rule 27 I-9.)
- DevTools Lighthouse on `/` reports the same accessibility score as the pre-WO-W baseline (zero new violations). Body text contrast unchanged from WO-V's tuning.

**Critical reminders.**

1. **`HeroPipelineVisual.tsx` is the rollback path.** Per Rule 27 I-2, do not edit it. It is imported by `AnimatedPipelineHero` for both the reduced-motion render path AND the mobile render path. If anything breaks, swapping the single import in `PersonaAwareHero.tsx` from `AnimatedPipelineHero` back to `HeroPipelineVisual` restores the previous behavior. Animation modules stay in the codebase, off-render.
2. **Reduced motion is the WCAG contract.** Per Rule 27 I-1, `useReducedMotion()` returning true means *zero* motion — no scale-in, no opacity ease, no parallax. If a designer asks for "just a tasteful fade", the answer is no. Reduced motion is not "less motion"; it's "no motion." This is binding under WCAG 2.1 SC 2.3.3.
3. **The 10 stage labels are public marketing copy.** Per Rule 27 I-3, `pipelineLayout.ts:PIPELINE_STAGES[].label` strings appear in marketing materials, pitch decks, and the Master Brief. Renaming or reordering requires coordination with marketing first. The "all 10 canonical stage labels" test is the tripwire — if a Cursor agent renames a stage without coordination, that test fails and the PR can't merge.
4. **No `filter:` on the animation critical path.** Per Rule 27 I-7. The "glow" effect comes from a stacked wider stroke beneath the bright beam, with `mix-blend-mode: screen` to interact with the lab-notebook canvas. The grep-based test prevents regression. If a designer pushes back wanting a "real glow", point them at the M3 MacBook → Moto G Power performance delta (40% framerate drop with `filter: drop-shadow()`) documented in this WO and the strategic doc.
5. **Beam palettes pass color-blindness simulation.** Per Rule 27 I-9. The primary contrast vector is brightness, not hue. A reviewer adding a new persona (e.g. "enterprise" with a corporate gray palette) must run the new palette through the deuteranopia/protanopia/tritanopia DevTools simulation before merging. The beam must remain perceptible.
6. **Composition with WO-V is one-way: WO-V exposes, WO-W consumes.** Per Rule 27 I-5. WO-V sets `data-persona` on `<section>`. WO-W reads it via `closest('[data-persona]')`. WO-V does not import any WO-W module. WO-W imports `PersonaId` type from WO-V's resolver because it's a leaf type — but importing copy or beam palettes would be a contract violation.
7. **The Skeptic emphasis is the marketing differentiator.** Per Rule 27 I-4. Brighter ring, larger background opacity, longer beam dwell on entry/exit. Every competitor's pipeline visual shows uniform agent boxes; ours screams "look at the Skeptic." Do not normalize Skeptic styling in a "consistency cleanup" — the asymmetry is the point.
8. **Animation is gated on viewport visibility.** Per Rule 27 I-6. If a future PR removes the IntersectionObserver gate, a user who scrolls past the hero and leaves the tab open accumulates 60fps × (10 minutes) = 36,000 wasted frames of beam math. Cheap CPU compared to the LLM pipeline, but pointless drain.
