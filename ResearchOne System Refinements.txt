## 4. Add a first-class research coordinating agent

Implement a dedicated `research_coordinator` or `quality_coordinator` role inside the existing research-run architecture. It must supervise one user run, not create a duplicate orchestration pipeline or a second report.

The coordinator owns the confirmed deliverable contract and evaluates bounded checkpoints:

1. Plan/contract completeness before discovery.
2. Usable evidence coverage after ingestion and retrieval.
3. Required specialist completion.
4. Draft contract and citation coverage.
5. Verifier/auditor results and targeted recovery.
6. Final terminal status.

Its output must use a strict validated schema such as:

* `continue`
* `recover`
* `block`
* deficiencies
* bounded recovery actions
* explanation

Allowed recovery actions should be narrowly enumerated, for example:

* Run additional discovery queries.
* Retry a required failed specialist once.
* Retrieve missing evidence classes.
* Repair specified structured fields.
* Retry a malformed verifier response.
* Block the report when recovery budgets are exhausted.

Persist coordinator checkpoint decisions in run telemetry so the UI and run summary explain what happened.

Deterministic gates remain authoritative. An LLM coordinator cannot declare success when exact counts, required fields, source thresholds, citation coverage, or verifier schemas fail. If the coordinator model fails, deterministic checkpoint logic must still produce a safe decision.

Use strict limits on rounds, calls, time, and tokens. No infinite recovery loops.
