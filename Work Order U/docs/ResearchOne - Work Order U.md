# Work Order U — Cost Telemetry Sidecar and Unit Economics Dashboard

**Goal.** Make every report's exact unit cost a first-class admin metric so we can (a) tune the V2 reasoner-class defaults toward cheapest-that-passes-forbidden-defaults, (b) price Sovereign Enterprise deals against real per-report cost rather than guesses (the $4,500/mo floor in the Master Brief was set on intuition; the WO-X academic-formatting work will further increase per-report token spend), (c) catch runaway reports before they blow a wallet hold, and (d) detect bottleneck agents (Skeptic running twice in a recovery loop, a Verifier eating 4× budget, a Discovery round exploding token count). The implementation is an in-process sidecar — `AsyncLocalStorage`-based run scope, fire-and-forget telemetry emit from a single instrumentation point in `callRoleModel`, a relational analytics-optimized table (`agent_executions`), and an admin dashboard with KPI scorecards, time-series, dimensional breakdown (phase/role/model), and a filterable per-run rollup table. Pricing is a DB-table configuration (`model_pricing`) with per-row price snapshotting so historical reports retain their original cost even after vendor price changes.

**Files to create.**

Schema migration `backend/src/db/migrations/030_cost_telemetry.sql`: see the prepared file. Creates `model_pricing` (seeded with current V1/V2/V2-skeptic model prices as of May 2026 per OpenRouter's public pricing page — operators update via SQL when providers change prices, no redeploy required), `agent_executions` (one row per LLM call, primary + fallback = two rows, indexed for the four admin queries), and the `report_cost_summary` view (per-run rollup, not materialized — at projected scale the underlying indexes make this trivial; promote to materialized only if row count exceeds 10M). Foreign keys are in `DO` blocks per Cursor rule 13. All `IF NOT EXISTS`-guarded for idempotent re-runs.

Sidecar services `backend/src/services/telemetry/`:

- `pricingCatalog.ts` — `getModelPrice(model)` with 60-second in-process TTL cache, deploy-skew-tolerant (Postgres `42P01` silently returns zero price during the rollout window), warn-once-per-unknown-model. `computeCostUsd(input, output, price)` is a pure function: `(input/1e6)*inPrice + (output/1e6)*outPrice`.
- `costSidecar.ts` — `runScope` (AsyncLocalStorage<RunScopeContext>, same pattern as `pool.ts:rlsStore`), `emitCallTelemetry(result, opts)` (fire-and-forget — calls `void writeRow(...).catch(...)` — Postgres `42P01` logged at DEBUG per Rule 25 I-6, `23505` idempotency replay logged at DEBUG per Rule 25 I-4, anything else at WARN with full context), `rolePhaseFor(role, callPurpose?)` (the canonical role→phase mapping covering all 17 `REASONING_MODEL_ROLES` entries — Rule 25 I-9 requires any new role to add its phase here in the same commit), `computeIdempotencyKey(...)` (sha256(`runId || role || startedAtMs || model`), hex-encoded — primary and fallback within the same call produce different keys because `model` differs, which is correct: both rows insert cleanly).
- `index.ts` — barrel exports of the public surface.

Cursor rule `.cursor/rules/25-cost-sidecar-and-unit-economics.mdc`: ten invariants. Most load-bearing are I-1 (single instrumentation point — `emitCallTelemetry` is only called from `callRoleModel`, never from orchestrator/discovery/revision/generator/extractors), I-2 (run scope set only by entry-point wrappers — never mid-function), I-3 (writes are non-blocking — `await` in the emit path creates a new failure mode for completing reports), I-5 (pricing is a DB-table configuration — code changes never required for vendor price updates), I-6 (deploy-skew tolerance — Postgres `42P01` is a known-tolerable state during migration rollout, do not escalate logging), I-8 (no RLS on `agent_executions` — admin-only data, all access via `adminQuery`), and I-9 (phase ≠ role; new roles must add their phase mapping in the same commit).

Admin endpoints (in `backend/src/api/routes/admin.ts`, see PATCH-07 for surgical insertion between the existing `/audit-log` handler and `export default router`):

- `GET /admin/cost/summary?days=N` — KPI totals: total_cost_usd, total_input_tokens, total_output_tokens, distinct_runs, distinct_reports, fallback_calls, plus derived avg_cost_per_run and fallback_rate.
- `GET /admin/cost/timeseries?days=N` — daily rollup points for the line chart.
- `GET /admin/cost/breakdown?days=N&dimension=phase|role|model` — pie/bar data. Dimension is sanitized via an explicit if/else mapping (not user-string-interpolation) so this is not a SQL injection vector — `costSidecarApi.test.ts` includes an attack-string test that asserts the response echoes `dimension='phase'` regardless of the input.
- `GET /admin/cost/reports?days=N&userId=...&phase=...&limit=50&offset=0` — paginated table of per-run rollups. Each row carries a `topPhase` (computed via a correlated subquery — the phase that ate the largest cost slice for that run, shown as a colored badge in the table to surface the bottleneck-agent insight).

Frontend page `frontend/src/pages/admin/CostAnalytics.tsx`: KPI cards (Total Cost / Avg Cost per Run / Total Tokens / Fallback Rate, with icons from lucide-react), time-series line chart (recharts `LineChart`), dimension toggle (phase / role / model) feeding side-by-side pie + bar charts, and a filterable table with userId and phase filters. The `PHASE_COLORS` constant matches the backend's `PipelinePhase` enum exactly — both the pie/bar charts and the table's `topPhase` badge use the same color per phase so the dashboard reads coherently. Deploy-skew handling: when the API returns `{available:false, reason:'migration_pending'}`, the page renders an amber `<AlertCircle>` banner explaining the migration is pending — never a broken page.

Backfill script `backend/scripts/backfill-cost-from-model-log.ts`: reads `research_runs.model_log` JSONB and emits historical `agent_executions` rows using the same idempotency key as live emit (so re-running is safe — Rule 25 I-7). Three documented limitations: (1) per-call `started_at_ms` is approximated from `research_runs.created_at + cumulative durationMs offset` because the original `model_log` did not persist call start timestamps; (2) `call_purpose` is unavailable in historical data so contradiction-extraction calls surface as Reasoning instead of Contradiction Extraction; (3) `error_classification` is left NULL for historical fallback rows. Usage:
```bash
tsx backend/scripts/backfill-cost-from-model-log.ts --since=2026-01-01 --dry-run
tsx backend/scripts/backfill-cost-from-model-log.ts --since=2026-01-01
```

**Critical reminders.**

1. **The orchestrator's existing `research_runs.model_log` JSONB is NOT replaced.** It remains the primary source of truth per Rule 25 I-3 — the new `agent_executions` table is a relational denormalization purpose-built for analytics. If `agent_executions` ever diverges from `model_log` for a given run, `model_log` wins; the backfill script (`scripts/backfill-cost-from-model-log.ts`) is the reconciliation path.
2. **`emitCallTelemetry` lives ONLY in `callRoleModel`.** Grep after every PR: `grep -r "emitCallTelemetry" backend/src --include='*.ts' | grep -v __tests__ | grep -v telemetry/` must return exactly two hits, both in `openrouterService.ts` (primary success path + fallback success path). Per Rule 25 I-1, any other call site is a bug — adding emit to orchestrator/discovery/revision/generator/extractors would either double-emit (because they already call through `callRoleModel`) or create a new pathway that bypasses fallback handling. Either way it's wrong.
3. **`runScope.run` is called ONLY by the three top-level entry wrappers** (`runResearchJob`, `runDiscoveryOrchestrator`, `createReportRevision`). Grep: `grep -rn "runScope.run" backend/src --include='*.ts' | grep -v __tests__ | grep -v telemetry/` must return exactly three hits. Any other invocation either stomps the parent scope unintentionally or creates an unwrappable layering bug.
4. **The inner functions (`runResearchJobInner`, `runDiscoveryOrchestratorInner`, `createReportRevisionInner`) are intentionally NOT exported.** If anything imports them outside their own file, scope is bypassed and the emit-side telemetry rows land with `run_id IS NULL` — they'll show up in the "no-attribution" bucket on the dashboard, easy to spot. Per Cursor rule 17, after refactoring any of these three functions, grep for the inner-name and confirm zero external imports.
5. **Pricing changes are SQL edits, not code edits.** Per Rule 25 I-5, when OpenRouter raises a price: `INSERT INTO model_pricing (model, input_price_per_1m_usd, output_price_per_1m_usd, effective_from) VALUES (...);` and `UPDATE model_pricing SET effective_until = NOW() WHERE model = ... AND effective_until IS NULL;`. The 60-second TTL cache picks up the change in the next minute; no redeploy. **Historical rows keep their original price** because `agent_executions.input_price_per_1m_usd` was snapshotted from the catalog at emit time — this is the right semantics for analytics (the cost we actually paid that day) and is one of the load-bearing decisions in `docs/COST_SIDECAR_DESIGN.md`.
6. **Adding a new `ReasoningModelRole` requires adding its phase mapping in `costSidecar.ts:rolePhaseFor()` in the SAME commit.** Per Rule 25 I-9, otherwise the new role buckets as `'Other'` in analytics and the Skeptic-bottleneck and Reasoner-bottleneck analyses become wrong. This is explicit composition with WO-X — when the academic-formatting work adds `citation_formatter` to `REASONING_MODEL_ROLES`, the same PR must add `case 'citation_formatter': return 'Citation Mapping';` (or whatever the chosen phase) to `rolePhaseFor`.
7. **The four admin endpoints catch ONLY Postgres `42P01`.** Any other DB error escalates to `next(err)` and gets the existing 500 path. Do not be tempted to add a generic catch-all — operators rely on 5xx escalation for paging.
8. **Backfill is one-shot and idempotent — re-runs are safe.** Per Rule 25 I-7. But running the backfill while live emit is also happening (post-PATCH-01 traffic) is fine — both paths compute the same idempotency key for the same `(run_id, role, started_at_ms, model)`, and `ON CONFLICT DO NOTHING` resolves the race. The live-emit row always wins because the backfill's approximated `started_at_ms` (anchored to `created_at + cumulative offset`) will differ from the real ms-precision timestamp captured at run time; both rows will exist for that historical run, the backfill's approximation labeled with `metadata.backfilled=true`. Operators inspecting historical reports should filter on `metadata.backfilled = false` for the most accurate timestamps.
